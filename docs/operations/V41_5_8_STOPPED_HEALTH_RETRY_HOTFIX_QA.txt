TaskForge Server v41.5.8 / revision 410508: stopped/unhealthy auto-recovery hotfix
Date: 2026-10-21

Observed incident on B after v41.5.7 migration:
  Postgres=primary, 22 core apps=healthy, traffic_ready=True,
  8 optional apps=Exited(0/137) but updater reports
  healthcheck-failed:exited/unhealthy and failed=8.

ROOT CAUSE IN PREVIOUS RELEASE:
  ManagedUpdates.step evaluated a cached Docker unhealthy status for an
  exited/created container BEFORE the desired-running start branch.
  On each expired next_attempt this emitted _failed(), increasing the next
  retry again. Thus the service never reached backend.start().

FIX:
  - Stopped/created/dead containers use their own start recovery branch.
  - A repeat exit during the verification grace produces one failure and
    a bounded retry instead of spinning with docker start every 5s.
  - Existing explicit retry deadlines are respected.
  - On first v41.5.8 Agent load, old healthcheck-failed:exited/* records
    receive exactly one immediate attempt, guarded by the usual Primary
    role and fencing checks. This migration is durable per service.
  - Real standby / leader conflict / control fence never starts apps.
