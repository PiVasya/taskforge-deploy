  error: "template ... <.State.Health>: map has no entry for key Health"

ROOT CAUSE:
Docker CLI's Go template .State.Health access may fail if the map lacks
Health (normal for a stopped, staged container). Prior release recovered
with a fallback docker ps -a + raw JSON inspect; correct but expensive.
Go-template's `index .State "Health"` safely returns empty for an absent
map key and works with Docker missingkey=error; `with` preserves fallback.

V41.5.6 CHANGE:
All ten active code files using that fragile template are patched. No
Docker daemon settings, Compose profiles, health probe definitions or
HA polling intervals changed. Docker fallback is retained for genuinely
missing containers/daemon errors. No automatic RabbitMQ recreation or
changes to PostgreSQL, MinIO, Redis, etcd volumes.

TESTS:
- Go text/template missingkey=error reproducer on created/running and
  healthy/unhealthy container map data.
- Fake Docker updater confirms one inspect, zero fallbacks on present
  staged container with absent health field; missing container still
  triggers safe Docker listing and JSON fallback.
- full inherited server release suite and independent archive extraction.
