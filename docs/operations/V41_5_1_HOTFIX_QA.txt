FIXES
1. Retire TaskForge's legacy Watchtower without deleting volumes or touching
   another project's updater; prevent old replica re-home/verify paths from
   resurrecting or requiring Watchtower. Repeat ownership check periodically.
2. Bounded, fair registry checks in batches of up to 6 with 2 concurrent pulls;
   increase single large image timeout from 180 to 420 seconds; per-image
   persistent exponential retry (30s to 30m); allow explicit immediate check.
3. Preserve the last-good release across health flaps. New candidate requires
   continuous 60s healthy observation before replacing the rollback tag; avoid
   premature cleanup. Roll back a failing candidate if an old good image exists.
4. When 1C is disabled, migration does NOT forcibly restart unrelated healthy
   app/API/frontend/worker containers. Previously 7 could be recreated.
5. Keep independent registry thread status and explicit update_degraded line in
   cluster status, not confused with the public traffic readiness signal.
6. Release and telemetry revision bumped to 410501 so live migration proves the
   new Node Agent is running, rather than accepting the previous release.

NOT TESTED / LIMITATIONS
- No real A/B/C servers, GHCR network, physical sensors, Docker Engine mutation,
  PostgreSQL/Patroni switchover, Cloudflare DNS changes or Telegram delivery.
- Docker image update is subject to registry/network availability and per-node
  capacity. Single-instance service replacement is not an atomic zero-downtime
  rolling deployment. Backoff retries cannot force an unreachable registry.
- High VPS CPU steal is a host-provider condition, not cured by this patch.
- No EF migrations or persistent database volume operation introduced.
